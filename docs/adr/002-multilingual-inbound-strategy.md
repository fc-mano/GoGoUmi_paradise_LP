# ADR 002: 多言語対応とインバウンド向けコンテンツ最適化方針

## 1. Context（背景）
興居島を訪れる訪日外国人観光客（インバウンド）の増加に伴い、英語（en）、韓国語（ko）、繁体字中国語（zh）の多言語LPを展開することとなった。
その際、日本語版LPのコンテンツをそのまま直訳して掲載する場合、以下の課題やミスマッチが生じる懸念があった：

1. **ニーズの不一致と情報過多による離脱**:
   * 日本語版に含まれる「イベント募集（EVENT & SPACE RENTAL：マルシェ出店、DJイベント、ヨガ、撮影ロケ等）」は地元・国内の主催者向けであり、海外旅行者の主目的（離島観光、ビーチでのリラックス、手ぶらBBQ、カフェ）と乖離している。
   * 情報量が多すぎると「イベント貸切専門の施設なのか？個人でも利用できるのか？」という誤認を招くリスクがある。
2. **問い合わせ・運用のミスコミュニケーションリスク**:
   * 設備手配やイベント条件の交渉を多言語（Instagram DM）で行うことは店舗オペレーション上の負担が大きい。
3. **複数言語管理における更新漏れ・データ不整合リスク**:
   * 料金改定やメニュー変更時に、日本語版のみ更新されて他言語版が古い価格のまま残るデグレードリスク。

## 2. Decision（意思決定）

### 2.1 インバウンド向けコンテンツ最適化（引き算の設計）
* **イベント募集セクションの非表示**:
  * 多言語版（`en/prices.js`, `ko/prices.js`, `zh/prices.js`）から `eventRecruit` 定義を削除。
  * 多言語版 HTML から `#events` セクションおよびヘッダーナビの `EVENT` リンクを削除。
* **一般利用（貸卓・BBQ・カフェ・アクセス）への特化**:
  * インバウンド旅行者が求める「手ぶらBBQ」「アサイーボウル」「フェリーでのアクセス手順」にフォーカス。
  * 貸切に関しては、イベント主催者募集ではなく「少人数〜グループでのプライベート貸切（Private Charter）」のシンプルな案内のみを維持。
* **ネガティブ情報の非掲載方針**:
  * 持ち込み制限や決済制約等のネガティブに映る制約事項はあえて前面に出さず、ポジティブな体験価値訴求を優先。

### 2.2 多言語アーキテクチャとマスター突合テスト
* **静的ディレクトリ分離**: 各言語を独立したサブディレクトリ（`/en/`, `/ko/`, `/zh/`）として配置し、SEO（`hreflang` / `canonical`）およびCDNキャッシュ効率を最大化。
* **日本語マスター（Single Source of Truth）によるクロスバリデーション**:
  * 日本語版 `prices.js` をマスターデータと位置づけ、`tests/test_suite.js` にて他言語版の「金額数値（基本貸卓料、BBQ、全フード・ドリンクメニュー）」「品目数」「予約URL」が完全に一致しているかを自動突合。
  * 更新漏れや価格のズレを CI（GitHub Actions）で 100% 事前検知可能にする。

## 3. Consequences（影響・効果）
* **UX/CVRの向上**: 旅行者にとって必要な情報（BBQ・カフェ・フェリー）への到達速度が向上し、認知負荷を大幅に削減。
* **保守性の担保**: 言語ごとの仕様差分（イベント非表示）がテストとドキュメントによって明文化され、属人化を防止。
* **データ整合性の完全自動保証**: 日本語版の料金変更時に他言語側の更新漏れをCIで確実に防止。
